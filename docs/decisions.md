# Technical Decisions (TD)

Prefix `TD` · Baseline 0.1 · Last reviewed 2026-11-08
Conventions: [requirements/README.md](requirements/README.md). Change history: [change-log.md](change-log.md).

The `TD` and `TD-R` prefixes preserve the identifiers originally assigned to technical decisions and recommendations; the prefix does not determine the row's current section or decision basis. Section placement and the Decision basis field determine its current status. IDs are never reused or renumbered.

This file keeps **decisions the project owner has established** apart from **technologies and approaches that were only suggested, recommended or left open**. Do not treat anything in section 2 or 3 as decided.

**Decision basis:** ESTABLISHED (owner specified) · SUGGESTED (brief proposed it as a starting point) · RECOMMENDED (an AI assistant proposed it as advice; not a decision) · OPEN (not decided).

### Local demo password — owner decision, 2026-11-08

The project owner selected `test123` as the shared password for the five fictional demo accounts to make classroom demonstrations and testing easier. The value is intentionally public for local development only. The API must remain bound to loopback and `ALLOW_LAN=NO`. Never use this password for personal accounts, real students, hosted environments, or production. The checked-in `.env.example` uses it for new demo accounts; existing accounts keep their password until the guarded local reset command is run. Each account still receives its own Argon2id hash. This is a demo convention, not a production password policy and not an amendment to Requirements Baseline 0.1. Source: SRC-20.
